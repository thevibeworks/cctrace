cctrace web interface — two design directions

Two complete worlds for the same product, built on the same sample data so they can be judged on the same facts. Direction A was designed here, from our own instrument. Direction B adopts the Claude Design System as measured off claude.ai. Both are working pages: switch screens, flip themes, drag the playhead, open the inspector, resize to 390.

Athe recorderdesigned here · roll 8e4546b4, candidate 1 of 7

A trace is a recording, so the page is the chart it was written on. The paper advances with the clock — the blank between two rows is the wait between two requests, and an idle stretch over five minutes folds to a hatched band that says how long. Every row opens with its own pen stroke: light for time to first token, solid for the rest, inked by its channel. Mono everywhere, 25px rows, no radius above 2px. Dark is the instrument's screen at night; light is the paper roll on the desk.

what the cold review changed

Both directions were audited by reviewers with no build history, against the design instrument's own rubric. Both graded P0 on the first pass. What they caught is worth knowing before you look:

  • A was a skin. The requests view was the DevTools network panel with a texture behind it — the exact page the direction says it refuses. Fixed structurally: the paper now advances with the clock and every row carries its own stroke, so the ruled ground measures something and the list is a recording, not a table.
  • B's evidence lied. This container had no sans face at all, so every capture rendered B's 14px sans body as mono — the one thing that direction is. Fonts installed, everything recaptured.
  • Both hid facts at narrow widths (a clipped toolbar in A, values cut mid-token in B), both faked keyboard support (highlight without focus, and j/k firing while you typed in the filter), both asserted states they never showed, and both had a colour system where one ink carried two meanings. All fixed; the brand screens now show hover / focus / disabled-with-reason / loading / empty / error / select-to-purge / masked identity.
  • Three invented numbers were removed — including 41% under on the one view whose entire point is that the numbers reconcile. It is 19%.

What still stands against each: A's session, context and dashboard views are the shipped layouts re-inked — only the requests view is structurally new, and whether that is a defect or the point is your call. B reads as a generic Claude-coloured admin panel unless you use the two moves only it has — flip a turn to Wire, and open the drawer. Each direction's DESIGN.md carries the full audit.

the standing exit

Keeping today's UI is a real option and costs nothing: GitHub-dark, tabs, one accent, 11–13px mono. It is not bad — it is the category's default, which is exactly why it reads as a devtools panel rather than as ours. Read both proposals against it with bun src/cli.ts view <trace> --no-open --port 8791.

how to review

  • Open each demo full screen and drive it: j/k through rows, / to search, click a turn block, drag the playhead, open an icicle node, press esc.
  • Flip the theme on both. Dark is where the work happens; light must not be an afterthought.
  • Set the width to 390 and check what each one drops first.
  • Then answer one question: is cctrace a piece of lab equipment, or part of Claude? Everything else in these two files follows from that.
